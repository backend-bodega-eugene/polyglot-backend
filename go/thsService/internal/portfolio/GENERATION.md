# 分类持仓生成

App `/api/app/market/holdings` 和后台 `/api/admin/holdings/{userID}/{category}/generate` 共用分类候选池、分配及交易生成逻辑。

- 每分类随机8—12个非零持仓，代码不重复；每只随机40—50条交易记录。
- 独立生成候选池：A股40、港股30、美股36、ETF24、期货24、黄金相关16、可转债20；全球及其他合并A股/港股/美股/ETF并按代码去重。
- 名称和代码为参考标的，部分可包含历史证券，不进行实时上市状态核验。目录价格只用于生成；同代码存在可用行情快照时优先使用快照，其他参考价格轻微随机变化并保持dataStatus=mock。不扩展或修改行情接口返回列表。
- 随机抽取时预留各标的最小交易单位预算。资金不够时可降至8个，仍无法满足则返回400，保留原快照。
- 仓位按随机权重分配，成本与持仓天数有差异；历史闭合买卖与最后一笔建仓共同保证交易净数量、成本及持仓对应。当前无手续费，闭合买卖不产生已实现盈亏。
- 已保存的数据不自动升级，查询只读原快照；首次缺失、App显式传totalAssets、后台主动重新生成才应用新规则。空items是手动保存的空仓，不重新生成。
- 原有会员行锁、generation并发检查、分类隔离、原子替换及后台审计不变；无数据库迁移。旧版已停用positions及其独立portfolio数据维持原规则。
- 后台手动编辑不限制为8—12个或40—50条，继续沿用原来的0—50个标的、每只1—500条及交易账目规则。生成后可立即在后台编辑保存。
