# 个人所得税 App 接口说明

从原始安装包 `个人所得税.apk` 抽出。该文件与 `origin.apk` 的 SHA-256 相同：`0a07868d653a90c12d167c0603c416b1b376e31949a879f69fb7cb767ca48414`。

应用是 uni-app，appid `__UNI__1131FF9`，包名 `uni.UNI1131FF9`，版本 `1.0.3`（versionCode 103）。业务请求全部写在 `assets/apps/__UNI__1131FF9/www/app-service.js`。`D:\apk_work\unpacked` 里的同名脚本已经被本地模拟替换过，下面的接口以 APK 内未改动的脚本为准。

业务接口一共 10 个。uView 自带的 `uni.request` / `uni.uploadFile` 封装没有再指向别的业务地址。

下面每个接口都附了返回示例，结构与 `D:\suodeshui\api-dump` 里已保存的样本一致。年度明细只展开一条，同一次返回里其余月份字段相同。

## 通用约定

| 项 | 值 |
| --- | --- |
| Base URL | `http://38.95.75.105/` |
| 方法 | 全部 `POST` |
| Body | JSON 对象。uni.request 对对象默认 `Content-Type: application/json` |
| 鉴权 | storage 里有 `token` 时，请求头带 `Authorization: Bearer {token}`。登录接口也会带 |
| 成功 | HTTP 200，且 `code == 1`，resolve 整个 body |
| 业务失败 | HTTP 200 但 `code != 1`，提示 `msg`，Promise reject |
| 登录过期 | HTTP 401，提示后 `reLaunch` 到 `/pages/login/login` |
| Loading | `v1/tax-user/taxYear/list` 和 `v1/tax-user/info` 不转圈，其余接口请求时 `showLoading` |

外壳：

```json
{ "code": 1, "msg": "success", "data": {} }
```

消息列表在外壳上多一个 `count`。

客户端封装在模块里导出为 `$api`：

- `login(data)` → `v1/tax-user/login`
- `userGet(data)` → `v1/tax-user/info`
- `companyGet(data)` → `v1/tax-user/company/list`
- `taxYearGet(data)` → `v1/tax-user/taxYear/list`
- `taxApplyInfoGet(data)` → `v1/tax-user/applyInfo`
- `puppeteerImg(data)` → `v1/tax-user/puppeteerImg`
- `openRecordList(data)` → `v1/tax-user/openRecord/list`
- `openRecordInfo(data)` → `v1/tax-user/openRecord/info`
- `taxCountInfo(data)` → `v1/tax-user/taxCountInfo`
- `taxMsgList(data)` → `v1/tax-user/taxMsg/list`

## 1. 登录

- 路径：`POST /v1/tax-user/login`
- 调用：`pages/login/login.vue`，`$api.login({ phone, pwd })`
- 按钮在手机号和密码都有值时才可点

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| phone | string | 是 | 手机号 |
| pwd | string | 是 | 密码 |

响应 `data.token` 写入 storage 键 `token`。

返回示例：

```json
{
  "code": 1,
  "msg": "登录成功",
  "data": {
    "token": "07e14b6d1fc1b8bc03d7f72318e82145f6c9dfd74adf48d54bea14a86f0a26c0"
  }
}
```

## 4. 年度收入纳税明细

- 路径：`POST /v1/tax-user/taxYear/list`
- 调用：收入纳税明细列表页，`$api.taxYearGet({ year })`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| year | string 或 number | 是 | 纳税年度 |

| 字段 | 说明 |

| zhaiyao | 摘要 |
| expect_date | 税款所属期。列表展示时截成前 7 位（YYYY-MM） |

| tax_name / channel / xiaolei | 所得项目、申报渠道、所得小类 |
| obligor_name / tax_num / tax_authority | 扣缴义务人、识别号、主管税务机关 |
| company_name / company_num / tax_company / post | 单位、编号、任职单位、职务 |
| start_date / end_date | 任职、离职日期 |
| income / tax | 收入、已缴税额 |
| rate / susuanCount | 税率、速算扣除数 |

## 5. 年度汇算申报

- 路径：`POST /v1/tax-user/applyInfo`
- 调用：`pages/home/applyInfo`，`$api.taxApplyInfoGet({ date })`
- 页面路由参数名是 `year`，请求字段名是 `date`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| date | string 或 number | 是 | 年份，例如 2024 |

| 字段 | 说明 |
| --- | --- |
| year | 年份 |
| total_income | 收入合计 |
| total_tax | 已缴税额 |
| refund_amount | 退税金额 |
| status | 申报状态 |

页面上展示的退税金额不取这个接口，而取用户资料里的 `tax_back_money`。

返回示例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "year": 2024,
    "total_income": 0,
    "total_tax": 0,
    "refund_amount": 0,
    "status": "未申报"
  }
}
```

## 6. 生成纳税记录开具图片

- 路径：`POST /v1/tax-user/puppeteerImg`
- 调用：`pages/home/taxRecordOpen.vue`，滑块通过后 `$api.puppeteerImg({ start_date, end_date })`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| start_date | string | 是 | 开始所属期，`YYYY-MM`，默认当前年月 |
| end_date | string | 是 | 结束所属期，`YYYY-MM`，默认当前年月 |

成功后客户端不读 `data`，提示生成成功并进入开具记录页。

返回示例：

```json
{
  "code": 1,
  "msg": "生成成功",
  "data": {}
}
```

## 7. 纳税记录开具列表

- 路径：`POST /v1/tax-user/openRecord/list`
- 调用：`pages/home/taxRecordOpen2.vue`，`$api.openRecordList({})`

无业务参数。`data` 为数组：

| 字段 | 说明 |
| --- | --- |
| id | 记录 id |
| create_time | Unix 秒，展示为 `YYYY-MM-DD HH:mm:ss` |
| images_data | 逗号分隔的图片地址，可保存到相册 |
| start_date / end_date | 所属期起止 |

返回示例：

```json
{
  "code": 1,
  "msg": "success",
  "data": [
    {
      "id": 18,
      "create_time": 1787607516000,
      "images_data": "",
      "start_date": "2026-08",
      "end_date": "2026-08"
    }
  ]
}
```

## 8. 扫码查看开具记录

- 路径：`POST /v1/tax-user/openRecord/info`
- 调用：首页和服务页扫码。二维码文本按 `-=` 切开，第二段作为验证码

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| yzm | string | 是 | 二维码里 `-=` 后面的那段 |

客户端读取 `data.images_data`，再带到 `/pages/home/scanQrRes`。

已保存样本是缺验证码时的返回：

```json
{
  "code": 0,
  "msg": "缺少验证码",
  "data": {}
}
```

验证码正确时，页面要读到的成功形状：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "images_data": "https://example.com/record-1.png,https://example.com/record-2.png"
  }
}
```

## 9. 消息列表

- 路径：`POST /v1/tax-user/taxMsg/list`
- 调用：进入消息组件时若没有 token 会去登录。`$api.taxMsgList({ page, limit: 10 })`
- 返回条数未达到 `count` 时 `page` 加 1 再请求，结果 `concat` 到列表

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| page | number | 是 | 从 1 开始 |
| limit | number | 是 | 固定 10 |

响应除 `code`、`msg`、`data` 外还有 `count`（总条数）。现有样本 `data` 是空数组，条目字段在逻辑里没有被点名。

返回示例：

```json
{
  "code": 1,
  "msg": "success",
  "data": [],
  "count": 0
}
```

## 10. 纳税计算明细
